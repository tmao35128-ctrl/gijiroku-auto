## ■ プロンプト D：アプリ UI（フェーズ拡張版）

```
社用車貸出レビューアプリ「logoCR」の UI デザインカンバスを作ってください。
第一弾で作った社内向けレビューサイトを土台に、
将来フェーズまで含めた全体像を1つのカンバスに設計したいです。

前提：Web アプリ（ネイティブアプリではない）。社員がスマホの QR から開くのが主導線なので
モバイルファースト（390x844）。デスクトップ版は主要画面のみ。

## プロジェクトの背景
自動車部品メーカー（ジヤトコ）の社内制度で、社員が福利厚生として日産車
（エクストレイル／オーラ、計7台）を借りられます。借りた社員がレビューを書き、
その声を品質改善に活かすと同時に、社員が日産車の魅力を体験する場にする制度です。
現在は SharePoint + Forms + Power Automate で運用しており、これをアプリ化します。

## カンバスの構成
カンバスを4つのフェーズブロックに分けて、左から右へ時系列で並べてください。
各ブロックの上に「PHASE 1 社内レビュー」のような見出しラベルを付けてください。
後のフェーズで追加される要素は、既存画面のどこに入るかが分かるように
ハイライト（点線の枠と番号バッジなど）で示してください。

---

### PHASE 1：社内レビューアプリ（ジヤトコ社員のみ）※最重要・最も作り込んでください

**1-1. ホーム（レビュー一覧）**
- 最上部に logoCR のロゴ
- その下に丸型（円形）ナビゲーションボタン3つ：「投稿」「車種一覧」「静岡県販売店情報」
  → Instagram ストーリーズ風の円形アイコン＋下にラベル。押したくなる見た目に。
- 並び替えコントロール：「新着順 / 評価が高い順 / いいねが多い順」
- レビューの縦リスト。YouTube のコメント欄のような、境界が強すぎない、
  テキストが主役の読みやすいリスト。1件あたり：
  イニシャルの丸アバター / ニックネーム / 星評価（★5段階・半星対応） /
  相対日時（「3日前」） / 車種タグ / 本文（長い場合は「続きを読む」） /
  いいねボタン（アイコン＋件数、押下後の状態も別に）
- 上部に「返却した車のレビューがまだです」というリマインドバナーの状態も1枚

**1-2. ホーム：並び替えメニューを開いた状態**（ボトムシート案とセグメント案の両方）

**1-3. レビュー投稿画面**
- ニックネーム / 星評価（大きめの★5つ・タップ選択） / レビュー本文（文字数カウンター付き）
- ＋「気になった点・不具合」の任意入力欄（開発部へのフィードバック用。任意であることを明示）
- 大きな「投稿する」ボタン
- **60秒で書き終わる軽さ**が伝わる設計にしてください

**1-4. 投稿：未入力エラー状態**
- 1つでも空欄なら「全部必須です」と出ます。
  ブラウザ標準 alert ではなく、世界観に合ったモーダル／トーストの案をください。
- 空欄フィールド自体にもエラー表示を付けたバージョンも

**1-5. 投稿完了 → ホームに戻り、自分の投稿が一番上に出ている状態**（成功トースト付き）

**1-6. 車種一覧**
- 「運行中の車」セクション：エクストレイル／オーラ（計7台）。
  写真・車種名・グレード・色・台数・特徴・平均★
- 「人気の日産車」セクション：セレナ／ノート／サクラ／アリア／キックス など。
  購買意欲を高める紹介カード中心
- カードは車の写真が主役。横スクロールカルーセルかグリッドか提案してください

**1-7. 車種詳細**：ヒーロー画像 / スペック要点 / 平均★ / その車のレビュー抜粋

**1-8. 静岡県販売店情報 一覧**
- 店名・住所・電話・営業時間・定休日・店舗写真
- エリア（東部／中部／西部）で絞り込むタブかチップ
- カードを押すと販売店の公式ホームページへ遷移することが分かる外部リンクアイコン

**1-9. マイページ**
- 自分の貸出履歴（いつ・どの車を借りたか）
- レビュー未投稿の車を目立たせる（「レビューを書く」導線）
- 自分が投稿したレビューと、もらったいいね数

**1-10. 管理ダッシュボード（事務局用・デスクトップ 1440x900）**
- レビュー投稿率 / 車種別平均評価 / 月別投稿数
- 「気になった点・不具合」だけを抜き出した、開発部提出用のリスト

**1-11. 空状態・ローディング**（レビュー0件、読み込み中スケルトン）

**2-4. シェアカード / QR ポスター**（社内掲示・名刺サイズの QR カード）

### PHASE 3：販売店コネクト ※このフェーズの狙いが伝わるように

社員が「この車に乗りたい」と思ったとき、アプリから静岡の販売店に直接つながり、
相談〜購入までの実績がアプリに記録されます。

**3-1. 車種詳細に追加されるボタン**
- 「この車について販売店に相談する」— Phase 1 の車種詳細のどこに入るかをハイライトで

**3-2. 販売店を選ぶ画面**
- 近い順 / エリア別に販売店を選択。各店の対応可否や営業時間も

**3-3. 連絡手段を選ぶ画面**
- 「電話する」「チャットで相談する」「来店を予約する」の3択カード

**3-4. チャットボット画面**
- 車種・希望条件を聞いてくれる会話 UI。最後に販売店へ引き継ぐ

**3-5. 相談ステータス画面（社員側）**
- 相談中 → 来店 → 試乗 → 商談 → 購入 の**進捗ステッパー**
- 各段階の日付と担当販売店

**3-6. 来店用の紹介コード / QR 画面**
- 社員が販売店で提示する画面。大きな QR と紹介コード

**3-7. マイページに追加される「相談履歴」**

**3-8. 販売店向け管理画面（デスクトップ 1440x900）**
- 自店に来た送客一覧（匿名の紹介コード単位）
- ステータス更新（来店した / 試乗した / 商談中 / 成約）
- 月次の実績入力フォーム（できるだけ入力項目を少なく、3分で終わる設計に）

**3-9. ジヤトコ側 KPI ダッシュボード（デスクトップ）**
- 送客 → 来店 → 試乗 → 商談 → 成約 のファネル
- 販売店別・車種別の内訳
- レビュー数と送客数の相関

**4-1. 試乗会イベント一覧・詳細・申込**（静岡県の販売店が開催する試乗会）
**4-2. 貸出車の予約カレンダーと申請画面**（現行 Forms からの移行後のイメージ）
**4-3. レビュー種別タブが増えたホーム**
  「社用車レビュー / 試乗レビュー / 販売店レビュー」の3タブ
**4-4. 販売店レビューの投稿画面**（※関係性に配慮が必要なため、
  「販売店だけに見える非公開フィードバック」モードの案も併せてください）

## デザインの方向性
- 日産車を扱うので **クリーン・信頼感・少しだけスポーティ**。
  白〜ライトグレー基調、アクセントは日産らしい **レッド 1色**を差し色として。
  赤を面で使いすぎないこと。
- 角丸は大きめ（12〜16px）、影は薄く、フラット寄りで今っぽく。
- 日本語が主役なので、日本語フォントで読みやすい行間・字間に。
- **「社内システム感」を出さないこと。** 一般消費者向けのレビューサービスのような、
  見ていて楽しい雰囲気に。ただし Phase 3 の管理画面・ダッシュボードは
  業務ツールとして情報密度を優先してください（トーンを切り替えてOK）。
- 星評価・いいね・並び替えは、押せることが一目で分かるアフォーダンスを重視。
- アクセシビリティ：コントラスト比 4.5:1 以上、タップ領域 44x44px 以上。

## 一緒に出してほしいもの
- カラーパレット（ベース／サーフェス／テキスト／アクセント／成功・警告・エラー）
- タイポグラフィスケール
- コンポーネント一覧：ボタン / 入力欄 / 星評価 / いいね / タグ / カード /
  ステータスステッパー / バナー / ボトムシート / トースト / 空状態
- 各状態（通常 / ホバー / 押下 / 無効 / エラー / 選択中）
- Phase 1 の画面遷移フロー図（矢印でつないだもの）を1枚
```

## ■ プロンプト E：プロジェクト MAP（会議用資料）

```
社内会議で使う「プロジェクト全体像 MAP」のデザインカンバスを作ってください。
プロジェクターに映して説明し、そのまま印刷して配る資料としても使います。
アートボードは 1920x1080（16:9）を基本にしてください。

## プロジェクト概要（資料に書く内容）
- 名称：社用車貸出制度 レビューアプリ「logoCR」
- 主体：ジヤトコ株式会社（PoC プロジェクト）
- 現状：正社員向けに日産車（エクストレイル／オーラ 計7台）を貸出。
  レビューを集めて開発部へフィードバックし、品質確認に活かす。
  同時に「体験型福利厚生」として社員が日産車の魅力に触れる機会を作る。
  すでに稼働中で予約が殺到している。現行は SharePoint + Forms + Power Automate。
- 目指す姿：レビューアプリを起点に、社員の「乗りたい」を静岡県の日産販売店へつなぎ、
  相談・試乗・購入までの実績を可視化する地域連携プラットフォームにする。

## 作ってほしいアートボード

### 1. エグゼクティブサマリー（1枚で全部わかる表紙）
- 中央に大きく「体験を、地域の実績に変える。」のようなキャッチ（案を3つ提案してください）
- 3行の要約
- 4つのフェーズを小さく横並びで予告
- 主要数字のプレースホルダー（貸出台数 7台 / 対象 正社員 / エリア 静岡県）

### 2. フェーズロードマップ ★メインの1枚
横軸に時間（左→右）、4つのフェーズを大きなブロックで並べる。
各ブロックに：フェーズ名 / 公開範囲 / 追加される機能 / この段階で得られるもの。

- **PHASE 1 社内レビュー**（社員のみ）
  SharePoint からアプリ化。レビュー投稿・車種一覧・販売店情報・いいね・星評価・並び替え。
  得られるもの：レビュー資産、開発部への品質フィードバック
- **PHASE 2 外部公開**（＋販売店・関係企業が閲覧）
  QR / リンクで社外閲覧、公開前チェック、社外向け表示。
  得られるもの：社外への発信力、販売店との接点
- **PHASE 3 販売店コネクト**（＋販売店が書き込み）★ここが本命
  アプリから静岡の販売店へ直接コネクト（電話／チャットボット／来店予約）、
  相談記録・購入記録・購入元販売店をアプリに反映。
  得られるもの：送客実績と成約実績＝制度の効果を数字で証明できる
- **PHASE 4 地域プラットフォーム**（構想中）
  試乗会情報・貸出予約のアプリ内完結・試乗レビュー・販売店レビュー。

各フェーズの下に「このフェーズの完了条件（次に進む判断基準）」の欄も作ってください。

### 3. ステークホルダー価値マップ ★会議で一番効く1枚
中央にアプリを置き、4方向に関係者を配置。
それぞれに「提供するもの」と「得られるもの」を対で書く。

- **ジヤトコ社員**：得る＝実車を体験できる／気軽に販売店に相談できる。
  出す＝レビュー、率直な使用感
- **ジヤトコ**：得る＝品質フィードバック／福利厚生の効果を数字で示せる／
  日産グループ内での存在感。出す＝車両・運営・アプリ
- **静岡県の日産販売店**：得る＝実車に乗った後の確度の高い見込み客が広告費ゼロで来る。
  出す＝店舗情報、相談対応、実績の共有
- **日産**：得る＝実ユーザーの一次データ／試乗〜購入のファネル可視化／品質 FB。
  出す＝車両・ブランド

「Phase 1・2 だけでは販売店にメリットが立たない。Phase 3 の送客と
セットで初めて三方よしになる」という点が視覚的に伝わるようにしてください。

### 4. ユーザージャーニー
1人の社員を主人公にした横長のストーリー帯：
「制度を知る → 予約する → 借りる → 乗る → 返す → レビューを書く →
他の人のレビューを読む → この車が欲しくなる → 販売店に相談する →
試乗する → 購入する → 購入レビューを書く」
各ステップの下に「そのときアプリがすること」と「そのとき生まれるデータ」を並べてください。
どこがどのフェーズで実現するかを色分けで示してください。

### 5. システム構成図
- 現行（SharePoint / SharePoint List / Forms / Power Automate）
- 新（Web アプリ + データベース + 通知連携）
- 予約フローは Phase 1 では既存 Forms のまま残し、
  アプリからリンクするだけ、という関係が分かるように
- Phase 3 で販売店向け管理画面とデータが増える様子を、追加レイヤーとして表現

### 6. KPI ツリー
最上位「制度の効果を数字で証明する」から分解：
レビュー投稿率 → 投稿数・閲覧数 → 販売店への送客数 → 来店数 →
試乗数 → 商談数 → 成約台数。
各項目に目標値のプレースホルダー（□件）を置いてください。

### 7. リスクと打ち手
2列の表形式で。
- レビューが集まらない → 返却翌日の自動リマインド（QR 付き）／60秒で書ける投稿設計
- 販売店の協力が得られない → 全店同時展開はせず 1〜2 店舗のパイロットから
- 販売店ごとにシステムが違う → API 連携はせず、紹介コード＋月次の簡易報告フォーム
- 個人情報（誰が何を買ったか） → まずは匿名の集計値のみ。個人紐付けは同意の仕組みを作ってから
- 販売店レビューによる関係悪化 → 公開せず販売店だけに見える非公開フィードバックから
- 構想が大きすぎて着手できない → Phase 1 を最短で出す。DB 設計だけ Phase 3 を見据える

### 8. 決裁者向け「お願いしたいこと」
この会議で承認・協力してほしいことを3〜5項目、大きく。

## デザインの方向性
- 会議資料なので **とにかく読みやすさ最優先**。
  プロジェクターで後ろの席から読める文字サイズ（本文 20px 相当以上）。
- 白背景 + 濃いグレーの文字 + アクセント 1色（レッド）+ 補助 1色（ダークネイビー）。
  フェーズごとに濃淡でグラデーションをつけて時間の流れを表現してください。
- 図は矢印・アイコン・枠でシンプルに。装飾のためのイラストは入れないでください。
- 情報の階層（見出し／小見出し／本文／補足）をはっきり分けてください。
- 各アートボードの左上に通し番号とタイトル、右下にページ番号。
- 白黒印刷でも読めるよう、色だけに意味を持たせないでください
  （形・線種・ラベルでも区別できるように）。
```

## 使い方メモ

1. **プロンプト D** → アプリ UI。Phase 1 のブロックだけ先に詰めて実装に入る
2. **プロンプト E** → 会議資料。ステークホルダー価値マップとリスク表を軸に説明する
3. E の「ステークホルダー価値マップ」は販売店を口説くときの資料にも転用できる
