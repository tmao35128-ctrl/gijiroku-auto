# Handoff: logoCR — 社用車貸出レビューアプリ

ジヤトコ株式会社 PoC ／ 日産車（エクストレイル・オーラ 計7台）の社内貸出制度アプリ

---

## Overview

社員が福利厚生で借りた日産車のレビューを投稿・閲覧し、その「乗りたい」を静岡県の日産販売店へつなぐ Web アプリ。現行の SharePoint + Forms + Power Automate 運用を置き換える。

4 フェーズで拡張する前提の設計。**Phase 1（社内レビュー＋予約）が今回の実装対象**、Phase 2〜4 は将来の受け皿として UI だけ用意してある。

- ネイティブアプリではなく **Web アプリ**
- 主導線は社内掲示の **QR → スマートフォン**。モバイルファースト（390×844）
- PC（1440×900）は Phase 1–2 が閲覧用、Phase 3 以降は事務局・販売店の業務ツール

## About the Design Files

このバンドルの HTML は **デザインリファレンス（プロトタイプ）** です。本番コードとしてコピーするものではありません。

意図された見た目・情報構造・状態遷移を示すものなので、**対象コードベースの既存環境（React / Vue / Next.js など）と既存のコンポーネント・パターンを使って作り直してください**。まだ環境がない場合は、プロジェクトに最も適したフレームワークを選定したうえで実装してください。

HTML 内の要素はすべてインラインスタイルで書かれています。これはプロトタイプの都合であり、実装ではコードベースのスタイル方針（CSS Modules / Tailwind / styled-components 等）に従ってください。

## Fidelity

**High-fidelity（hifi）**。色・タイポグラフィ・余白・状態はすべて確定値です。ピクセル単位で再現してください。ただし例外が 2 つあります。

- **Phase 4 の画面はラフ（lofi 相当）**。構想段階なので、レイアウトと情報項目の参考程度に。
- **写真はすべてプレースホルダー**（`image-slot`）。実写真は未提供。

## Screens / Views

### PHASE 1 — 社内レビュー（実装対象）

#### 1-1. ホーム（レビュー一覧）— モバイル / PC

**目的**：レビューを読む・並び替える・各機能へ入る。

モバイル：ステータスバー 44px → 白のヘッダー（ロゴ 22px/900、その下に **円形ナビ 3つ**）→ 並び替えチップ → レビューの縦リスト。

- 円形ナビ：直径 62px、`border: 2px solid #C3002F`、白地、下にラベル 11px。3 つを `justify-content: space-around`。「投稿」「車種一覧」「静岡県販売店情報」
- 並び替え：チップ 3 つ（新着順 / 評価が高い順 / いいねが多い順）。選択中は `#1A1C1F` 地に白文字、非選択は白地＋`#DEE0E4` 枠。横スクロール可
- レビュー 1 件：38px の円形イニシャルアバター（`#EDEEF0` 地）＋ 右カラム（ニックネーム 13px/700・相対日時 12px → ★（`#C3002F` 14px）＋車種タグ → 本文 14px/1.95 → いいね ♡ ＋ 件数）。**カード枠は付けない**。YouTube のコメント欄のような、境界が弱くテキストが主役のリスト

PC：72px の固定ヘッダー（ロゴ＋横並びナビ＋「レビューを書く」アウトラインボタン＋アバター）。本体は 2 カラム（左 1.6：レビューリストを白カードに内包 ／ 右 1：運行中の車・販売店の要約）。並び替えはセグメント（連結した 3 ボタン）。

#### 1-2. レビュー投稿 — モバイル

「60 秒で終わる」ことが伝わる軽さが要件。

- 上部にリマインドバナー（`#FDF3F5` 地、`#F3D3DA` 枠、12px、赤系文字）：「エクストレイル（返却日 9/2）のレビューがまだです。**60秒**で終わります。」
- ニックネーム：高さ 52px の入力欄
- 評価：★ 5 つを **42px** で表示、`letter-spacing: 2px`。未選択は `#DEE0E4`。半星対応
- 本文：min-height 150px、文字数カウンター（`38 / 500`、右寄せ 11px）
- 「気になった点・不具合」：**点線枠 `1px dashed #C9CDD2`＋`#F7F7F8` 地**で本体と区別。「任意」バッジ、「開発部へのフィードバックに使わせていただきます。空欄のままで投稿できます。」の注記。中に白い入力欄
- 投稿ボタン：高さ 56px、`#C3002F` 塗り、白 16px/700、radius 14px

**エラー**：1 つでも空欄なら、ブラウザ標準 `alert` ではなくアプリ内のモーダル／トーストで「全部必須です」。空欄フィールド自体にも赤枠＋エラーテキストを出す（既存の `logoCR UI Canvas.dc.html` に状態バリエーションあり）。

**投稿完了**：ホームへ戻り、自分の投稿が一番上。成功トーストを表示。

#### 1-3. 車種一覧 — モバイル

- 「運行中の車」：**1 カラムの縦カード**。写真（168px）→ 車種名 17px/700・グレード・平均★ → チップ（色／台数／レビュー件数）→ 特徴文 13px
- 「人気の日産車」：**横スクロールカルーセル**。カード幅 212px、写真 126px。セレナ／ノート／サクラ／アリア／キックス。購買意欲を高める短いコピー

意思決定が必要な運行中の車はグリッド、憧れを見せる人気車はカルーセル、という使い分け。

#### 1-4. 車種詳細 — モバイル

ヒーロー写真 230px → 車種名＋グレード → 平均★・件数 → スペック表（6 行、ラベル幅 110px）→「この車を予約する」（赤アウトライン）→ **Phase 3 で追加される「販売店に相談する」ボタンの位置を赤い点線枠＋ラベルで明示** → その車のレビュー抜粋。

#### 1-5. マイページ — モバイル

プロフィール（アバター 56px・レビュー数・もらったいいね）→ **未投稿アラート**（`#FDECEF` 地・`#F0B9C4` 枠、赤ボタン「レビューを書く」）→ 貸出履歴（未投稿は赤バッジ、投稿済は緑バッジ）→ 投稿したレビュー。

#### 1-6. 予約システム ★今回追加 — モバイル / PC

**要件**
1. 予約状況をカレンダーで見られる
2. **車種ごとにカレンダーを切り替えられる**
3. すでに予約が入っている日は色分けする
4. **空いている日は何もしない**（白のまま、マークも付けない）
5. 借りたい日・借りたい期間を指定できる
6. 満車のときは「満車です」と表示する

**車種スイッチャー**（モバイル：横スクロールのチップ列 ／ PC：3 枚の横並びカード）

| 状態 | border | background | 補助テキスト |
| --- | --- | --- | --- |
| 選択中 | `2px solid #C3002F` | `#FDECEF` | 「4台 ／ 表示中」`#C3002F` |
| 非選択 | `1px solid #DEE0E4` | `#FFFFFF` | 「2台」`#61666E` |

選択中はチップ自体で表現すること（下線バーのような分離した装飾は不可）。`min-height: 44px`。

**カレンダーセルの状態**（先頭に空白セル。2026/10 は 1 日が木曜なので 4 セル）

| 状態 | bg | border | 文字色 | 注記 |
| --- | --- | --- | --- | --- |
| 空き | `#FFFFFF` | `#E9EAEC` | `#1A1C1F` | **なし** |
| 一部予約あり | `#FDECEF` | `#F0B9C4` | `#1A1C1F` | 「残 n」`#C3002F` |
| 満車 | `#EDEEF0` | `#C2C6CB` | `#4E535A`（500） | 「満車」`#4E535A` |
| 選択中の期間 | `#C3002F` | `#C3002F` | `#FFFFFF`（700） | 「残 n」/「選択」白 85% |
| 選択中かつ満車 | `#EDEEF0` | `#C3002F` | `#4E535A`（700） | 「満車」`#A3002A` |

セル寸法：モバイル `aspect-ratio: .92`、gap 5px、日付 14px、注記 10px ／ PC 高さ 78px、gap 8px、日付 15px、注記 11px。曜日ヘッダーは日曜 `#C3002F`・土曜 `#1B2A41`。凡例 4 種（空き／一部予約あり／満車／選択中）を必ず表示。

**期間指定**：開始・終了の 2 フィールド（選択済みは `1px solid #C3002F`）。

- 空きがある場合：緑の確認バー（`#F2F9F4` / `#C6E3CF` / `#1B5C31`）「3日間・エクストレイル：この期間は空いています（残り 2台）」＋ 申請ボタン有効（赤塗り）
- **満車日を含む場合**：赤の警告ボックス（`#FDECEF` 地）「10/10・10/11 は満車です」＋「選択した期間に満車の日が含まれています。期間を変えるか、別の車種を選んでください。」＋ **近い日程の空き候補を 2 件提示** ＋ 申請ボタンを無効化（`#EDEEF0` 地／`#9AA0A6` 文字、ラベル「この期間では申請できません」）＋ 下に「満車の日を含む期間は申請ボタンが無効になります」

**制約**：連続貸出は最大 5 日。返却翌日にレビュー依頼通知。

**PC 版**：左 1.75（車種カード＋月カレンダー）／右 1（期間指定・今月の空き状況バー・直近の申請リスト）。

#### 1-7. 販売店情報一覧 — モバイル

エリア（東部／中部／西部）のチップで絞り込み。カードに店舗写真・店名・距離・営業時間・定休日。押すと公式サイトへ遷移することが分かる外部リンクアイコン（↗）。

#### 1-8. 管理ダッシュボード — PC（事務局用）

216px のネイビーサイドバー＋本体。KPI カード 4 枚（レビュー投稿率／今月の投稿数／平均評価／未投稿の返却）→ 月別投稿数の棒グラフ＋車種別平均評価のバー → **「気になった点・不具合」抽出リスト**（日付・車種・内容・評価、CSV 出力ボタン）。開発部提出用。

#### 1-9. 空状態・ローディング

レビュー 0 件の空状態、読み込み中のスケルトンは `logoCR UI Canvas.dc.html` に収録。

### PHASE 2 — 外部公開

- **社外向けランディング（モバイル）**：ヒーロー見出し 30px/900、3 行の説明、実績チップ（貸出 7台／レビュー 128件／静岡県）、写真、そのままレビュー一覧へスクロール

### PHASE 3 — 販売店コネクト（本命）

- **販売店を選ぶ（モバイル）**：近い順／エリア別のチップ。店舗写真・距離・営業時間・対応可否バッジ
- **チャットボット（モバイル）**：吹き出し（bot＝白＋`#E9EAEC` 枠 ／ 自分＝`#C3002F` 塗り）、サジェストチップ、最後に「この内容で販売店に引き継ぐ」カード → 紹介コード発行
- **連絡手段を選ぶ（モバイル）**：電話する／チャットで相談する／来店を予約する の 3 択カード（54px の円形アイコン）。下部にプライバシー注記
- **相談ステータス（モバイル）**：相談中 → 来店 → 試乗 → 商談 → 購入 のステッパー（完了＝赤丸に✓、現在＝赤枠に●、未達＝グレー）。各段階の日付と担当販売店。下に **大きな QR と紹介コード `JC-4821`**（28px/900）
- **販売店向け管理画面（PC）**：ダークブラウンのサイドバーで別システムであることを示す。送客一覧は**紹介コード単位の匿名**。ステータスはワンクリックで次段階へ。月次実績入力は 3 分で終わる項目数
- **ジヤトコ KPI ダッシュボード（PC）**：送客→来店→試乗→商談→成約のファネル、販売店別内訳、レビュー数と送客数の相関（散布図）

### PHASE 4 — 地域プラットフォーム（ラフ）

## Interactions & Behavior

- **並び替え**：チップ／セグメントをタップで即時リストを再取得。モバイルはボトムシート案も既存カンバスに収録
- **いいね**：楽観的更新。押下後は塗りアイコン＋件数 +1
- **続きを読む**：本文が 3 行を超えたら省略し「続きを読む」
- **投稿バリデーション**：ニックネーム・★・本文が必須。「気になった点・不具合」のみ任意。未入力があればアプリ内モーダル／トーストで通知し、該当フィールドに赤枠とエラーテキスト
- **予約の期間選択**：開始日タップ → 終了日タップで範囲確定。範囲内に満車日が 1 日でもあれば警告状態へ遷移し、送信を無効化。代替候補は同一車種の近接する空き期間と、他車種の同一期間から生成
- **カレンダーの車種切替**：選択中の車種 ID でその月の在庫状況を再計算（月の再取得は不要な設計が望ましい）
- **外部リンク**：販売店カードは公式サイトを別タブで開く（↗ アイコン必須）
- **リマインド**：返却翌日に QR 付きのレビュー依頼を送る（現行は Power Automate。移行方式は要検討）

## State Management

必要な状態の目安。

- `sortKey`: `'newest' | 'rating' | 'likes'`
- `reviews`: `{ id, nickname, initial, rating, carId, body, likes, likedByMe, createdAt, defectNote?, visibility }`
- `cars`: `{ id, name, grade, color, unitCount, avgRating, reviewCount, feature, photoUrl }`
- `availability`: `{ carId, date, total, booked }` → 派生で `free | partial | full`
- `reservationDraft`: `{ carId, startDate, endDate }` → 派生で `isValid`, `conflictDates[]`, `alternatives[]`
- `reservations`: `{ id, code, userId, carId, startDate, endDate, status }`
- `viewerMode`: `'internal' | 'public'`（Phase 2。公開モードでは投稿導線とマイページを出さない）
- Phase 3：`consultation { code, carId, dealerId, channel, stage, timeline[] }`

**Phase 1 の時点で、Phase 3 の相談・購入テーブルを見据えた DB 設計にしておくこと**（後戻りを避けるため）。個人情報は当面、匿名の集計値のみ扱う。

## Assets
