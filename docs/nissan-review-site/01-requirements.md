## 0. プロジェクト背景

### 制度の目的
ジヤトコ株式会社 PoC プロジェクト「社用車貸出制度」。

- **対象**: 正規社員
- **内容**: 日産車を貸出 → 貸出後にレビューを書く → PDCA を回す
- **アウトプット**: レビューから出た課題・車に対する懸念を開発部へ報告し、ジヤトコおよび日産車の FB として品質確認に使う
- **コンセプト**: 体験型福利厚生。社員が実際に乗って触れることで購買意欲を高め、日産車の魅力を感じる機会を設ける

### 現状
- プロジェクトは**すでに稼働中**、予約が殺到している
- 運営構成: SharePoint Site + SharePoint List + Forms + Power Automate

### 社長の意向
- **外部の人（販売店・関係企業）がレビューを閲覧できるようにしたい**
- **QR コード / リンクから開けるようにしたい**

### 担当者（私）の考え
- 予約とレビューを 1 つにまとめたい
- ただし予約は既存の申請フォーマットがあり、変更すると
  - 申請時のメール通知先
  - 承認後のフロー
  - 現フォーマットで行っている動作
  を完全に引き継ぐ必要があるため、統合するかは**保留・要検討**

## 3. 技術スタック（たたき台 / 要相談）

### 3-1. 前提となる制約
- **社外の人（販売店・関係企業）が QR / リンクで開ける**必要がある
  → SharePoint は社内 Entra ID 認証が前提のため、**外部公開用は SharePoint の外に置く**のが現実的
- 社内の予約フローは Forms + Power Automate のまま**壊さない**

### 3-2. 推奨案（第一候補）

| レイヤー | 技術 | 理由 |
|----------|------|------|
| 言語 | **TypeScript** | 型があるほうが後から人が増えても壊れにくい |
| フロント | **Next.js (App Router) + React** | Web サイト要件に合致。SSR/ISR で QR から開いたときの表示が速い。SEO 不要でも初期表示が軽い |
| スタイル | **Tailwind CSS** | Claude Design の出力をそのままコードに落とし込みやすい |
| DB / API | **Supabase (PostgreSQL)** | 無料枠あり。テーブル定義だけで REST/JS クライアントが生える。RLS で「閲覧は誰でも / 投稿は制限」を宣言的に書ける |
| ホスティング | **Vercel** | Next.js と相性最良。Push だけでデプロイ。独自ドメイン + HTTPS が即用意でき QR にしやすい |
| 画像 | Supabase Storage | 車種写真・販売店写真 |

### 3-3. 代替案

| 案 | 構成 | 向き / 不向き |
|----|------|---------------|
| A. 軽量案 | 静的 HTML/CSS/JS + Google スプレッドシート + GAS | 一番安く速く出せる。ただし件数が増えると遅い・権限管理が弱い |
| B. Microsoft 寄せ | Power Pages + Dataverse | 社内資産と統合しやすいがライセンス費用と外部公開設定のハードルが高い |
| C. Firebase 案 | Next.js + Firestore + Firebase Hosting | Supabase 案とほぼ同等。SQL で並び替え・集計をしたいので Postgres の Supabase を推す |

### 3-4. データモデル案

```
cars            -- 車両マスタ
  id, model_name(エクストレイル/オーラ), grade, body_color,
  image_url, is_in_service(運行中フラグ), is_popular(人気車フラグ),
  seats, description, sort_order

reviews         -- レビュー投稿
  id, car_id(FK, 任意), nickname, rating(1-5), body,
  like_count, created_at, status(公開/非公開/要確認)

review_likes    -- いいね重複防止
  review_id, visitor_token(ブラウザ側で発行), created_at
  UNIQUE(review_id, visitor_token)

dealers         -- 静岡県販売店
  id, name, address, tel, business_hours, holiday,
  website_url, image_url, area(東部/中部/西部), sort_order
```

並び替え（要件 #10）は `ORDER BY rating DESC` / `created_at DESC` / `like_count DESC` で対応。

## 4. 予約との統合について（結論保留）

**推奨: フェーズ分けする。**

| フェーズ | 内容 |
|----------|------|
| Phase 1（今回） | **レビューサイトのみ**を新規に作る。予約は既存の Forms + Power Automate をそのまま維持。レビューサイトからは「予約はこちら」で既存 Forms へリンクするだけ |
| Phase 2 | 返却時に Power Automate から「レビューお願いします」の QR / リンクを自動送信し、レビューサイトへ誘導 |
| Phase 3 | 予約データ（車種・貸出期間）を Power Automate → Webhook で DB に連携し、レビューと紐付ける |
| Phase 4 | 予約申請自体の移行を検討（メール通知先・承認フロー・既存動作の完全再現ができると確認できてから） |

こうすれば**既存の予約フローを 1 ミリも壊さずに**、社長の要望（外部公開・QR）を先に満たせる。
